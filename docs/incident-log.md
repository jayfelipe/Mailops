INC-001 — DER walk read content-start where it needed the sibling offset
Date: 2026-10-13Symptom: 4 test failures. rsa_modulus_bits raised "expected BIT STRING"on structurally valid RSA keys; downstream, check_record reported validkeys as "not valid base64".Diagnosis: DER is tag-length-value. After reading a TLV, its contentstart (i) and its end (end) are different pointers: enter a container ati, skip to the next sibling at end. The outer walk entered instead ofskipping after the AlgorithmIdentifier, landing on the OID inside it(byte 6) instead of the BIT STRING (byte 19). The fixture repr in the testoutput showed the 0x03 sitting right where the code wasn't looking.Fix: Second walk step jumps to the algid's end. Also split base64decoding from DER parsing in check_record — one ValueError was beingmapped to "invalid base64" regardless of which layer actually failed.Lesson: (1) In TLV formats, "where content begins" and "where the nextthing lives" are different pointers. (2) Error messages must name the layerthat failed, or they send the responder looking at the wrong component.(3) A passing test can pass for the wrong reason — test_testing_mode_flaggedwas green because t=y is evaluated before key parsing, not because thekey path worked.
